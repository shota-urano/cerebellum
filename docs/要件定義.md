# cerebellum 要件定義書

作成: 2026-07-25 / 状態: ドラフト（レビュー待ち）

## 1. 背景・目的

second-brain の各ルーチン（daily-tasks 等）は現在 Slack へ通知しているが、以下の問題がある。

- 他のSlackメッセージに埋もれ、チェックスレッドに戻るのが面倒
- Slack mrkdwn の制約で文章が読みづらい
- 下書き等のコピペがしにくい
- ✅リアクションによる消し込み・承認はハックであり操作性が悪い

これらを解決する**自分専用の運用ダッシュボードアプリ**を作り、最終的に Slack 運用を完全に置き換える。

## 2. 全体方針（確定事項）

| 項目 | 決定 |
|---|---|
| データ正本 | 常に Vault（second-brain）の md。アプリは Vault を**読み取りのみ**（書き込まない） |
| アプリの状態 | ローカル SQLite に保存（消し込み履歴等） |
| 構成 | ローカル完結。外部サービス（Supabase等）は使わない |
| スマホ対応 | Tailscale 経由で自宅Macのサーバーへアクセス（導入済み） |
| Slack | **完全置き換えが最終目標**。通知の自前実装が完了するまでは Slack 通知のみ暫定継続 |
| 公開 | インターネットには公開しない（Tailnet内のみ） |

## 3. 技術スタック

- **バックエンド: Rust（axum）** — 単一バイナリ。サブコマンド式 CLI を兼ねる
  - `cerebellum serve --port 48210` : APIサーバー＋フロント静的配信
  - 将来: `cerebellum notify` 等のバッチサブコマンド
  - SQLite は rusqlite（または sqlx）で扱う
- **フロントエンド: Next.js** — `output: 'export'` の静的出力を Rust が配信
- デプロイ = バイナリ1個＋静的assets。launchd で常駐
- verify 契約: `cargo build / test / clippy` ＋ `next lint / build`（dev-loop 前提）

## 4. 機能要件

### Phase 1（v1・今回の実装範囲）: 日々のTODOチェック

- **F1. 今日のタスク表示**
  - 正本 `80_運用ガイド/人間のルーティン.md` の表をパースし、今日分を抽出して表示
  - 抽出仕様は `daily-tasks/scripts/post.py` と同一（毎日／平日／週末／曜日、`<br>`→` / `、時刻順ソート）
  - タスクIDは (間隔|時刻|内容) のハッシュで安定化
- **F2. 消し込み**
  - タップでチェックON/OFF。状態は SQLite に `(date, task_id, done, checked_at)` で記録
  - 正本 md は変更しない
- **F3. 過去分の閲覧**
  - 日付を遡って過去のタスクと消し込み状態を見られる（カレンダー or 日付ナビ）
  - 過去日の表示はその日の記録（スナップショット）を正とする。記録が無い日は「記録なし」表示
  - **過去日は読み取り専用**（消し込みの後日変更は不可。変更できるのは当日分のみ）
  - 達成率などの簡単なサマリ（例: 直近7日の消化率）
- **F4. 記録の確定**
  - その日の対象タスク一覧は、初回表示時（またはサーバーの日次処理時）に SQLite にスナップショットとして保存する。正本の表を後日編集しても過去の記録は変わらない

### Phase 2 以降（将来像・今回は実装しない）

- 下書き一覧＋ワンタップコピー（reply-assist / x-smart-post / x-quote-rt の draft）
- 承認フロー（night-harness 等の採用提案に承認→ `--apply` 系がSQLiteを読む）
- digest・朝レポ・週報の整形閲覧
- 通知の自前実装（PWAプッシュ＋Tailscale HTTPS、または ntfy.sh 併用）→ 完了時点で Slack を廃止
- メトリクス可視化（views / ER / PDCA）

## 5. 非機能要件

- スマホ（iOS Safari）とPCブラウザの両方で操作しやすいこと（レスポンシブ、タップターゲット44px以上）
- 常時ダーク（2026-07-26 デザイン確定でOS追従から変更。light テーマは持たない）
- サーバー再起動でデータが消えないこと（SQLite永続化）
- Vault が Google Drive 同期中で一時的に読めない場合もクラッシュせずエラー表示すること
- 依存サービスゼロ（オフラインの自宅ネットワークでも動く）

## 6. データモデル（ラフ）

```
task_days   (date TEXT, task_id TEXT, interval TEXT, time TEXT,
             effort TEXT, tool TEXT, content TEXT,
             PRIMARY KEY (date, task_id))          -- その日のスナップショット
task_checks (date TEXT, task_id TEXT, done INTEGER,
             checked_at TEXT,
             PRIMARY KEY (date, task_id))          -- 消し込み状態
```

## 7. 画面（ラフ）

1. **今日** … タスク一覧（時刻・工数・ツール表示）、タップで消し込み、進捗カウント
2. **履歴** … 日付ナビ＋その日のタスク一覧（読み取り専用）、直近7日サマリ

## 8. 制約・禁止事項

- Vault のファイルへ書き込まない（読み取り専用）
- 既存スキル・routine の動作を壊さない（Phase 1 では既存フローに変更を加えない）
- インターネット公開・外部送信をしない
