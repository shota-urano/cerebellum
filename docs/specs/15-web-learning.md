# 15. 学習セッションビュー仕様（画面）

**親**: [`00-overview.md`](./00-overview.md) ｜ **担当**: Frontend ｜ **範囲**: `app/learning/page.tsx`・`features/learning/`・「今日」画面の詳細導線

## 1. 目的

「今日」のタスク **「40_Projectsにて新たな学習」** をタップしたら、**レッスン → 問題（回答を入力）→ 採点 → 当日の感想** の一本道を歩いて、最後にタスクが消し込まれる。見えるのは常に今日の1セットだけ——リストも在庫も出さない（当日集中モデル・2026-07-29 ユーザー決定）。「溜まっていくプレッシャー」を構造的に発生させない。

## 2. 入出力

- **入力**: `GET /api/learning/sets/{date}`（[`14-learning.md`](./14-learning.md)）。タスク側の `detailRef = learning.session` は `GET /api/days/{date}` の DTO に含まれる
- **出力**: `POST /api/learning/sets/{date}/result`（自己採点＋感想）、既存 `POST /api/days/today/checks/{taskId}`（消し込み）
- **経路**: `/learning?date=YYYY-MM-DD&taskId=...`（date 省略時は今日）。「今日」画面のタップ分割規約は [`12-web-digest.md`](./12-web-digest.md) §のとおり（`detailRef` 持ちの行は面全体が遷移）

## 3. 処理詳細

ステッパー4段。上部に `レッスン ─ 問題 ─ 採点 ─ 感想` の進捗インジケータ（**通過済みの段はタップで戻れる**。先の段への飛び越しは不可）。md 描画・パネル様式はダイジェスト詳細（`panel dg`）と同じ。

> 2026-07-31 改訂（USL-282）: 「回答」段を「採点」に改称し、問題段に回答フォームを導入した。旧仕様の「入力を求めない」は code 問題と体験が割れるためだったが、code 問題の新規生成を廃止（[`14`](./14-learning.md) §4）したため前提が消えた。

### 3.1 レッスン

- 見出し: `今日の学習 — {theme}`
- `lesson_md` を表示 → 下部ボタン「問題へ」

### 3.2 問題

- `problems[]` を1問ずつカードで表示（`no`・`question_md`）
- **`answerType` を持つ問題は回答フォームを付ける**: `choice` は選択肢（`choices[]`）のラジオボタン、`number`・`text` は1行テキスト入力。入力はローカル state
- **`number` 問題には折りたたみ式の「計算メモ」を付ける**: 四則演算・括弧・小数・%を安全な画面内パーサーで計算し、式と結果を問題ごとの履歴へ追記する。数字・演算子・括弧・`ANS`（直前結果）は画面内キーでも入力でき、履歴の任意の結果は次の式へ再利用できる。最新結果はそのまま／切り上げ／切り捨て／四捨五入して回答欄へ反映できる
- 計算メモの式・履歴は回答入力・採点と同じローカル state。通過済みの段へ戻っても保持するが、途中離脱では永続しない。APIへ送るのは従来どおり最終回答だけで、式・履歴は送らない
- `answerType` の無い問題（旧形式・code 問題）はフォームなし——従来どおり頭の中で答えてから進む
- `kind = "code"` の問題は `workdir` パスを**コピーボタン付き**で表示し、「ターミナルで解いてから戻ってきてください」の一文を添える（解く行為はこの画面の外。verify もターミナルの領分）
- 下部ボタン「採点へ」——**未回答の問題があっても進める**（分からない問題を飛ばせる。未回答は採点段で×になる）

### 3.3 採点

- 各問題カードに `answer_md`（正解と解説）を展開する
- **`answerType` を持つ問題は自動採点**: ユーザー入力と `expected` を比較して ○ / × を表示（未回答は × に「未回答」を添える）。比較則——共通: 前後空白トリム＋NFKC 正規化（全角/半角）＋大文字小文字無視。`number`: 双方を数値として解釈して比較（`12.5` = `12.50`。解釈不能は×）。`choice`: 選択値と `expected` の完全一致
- 自動採点の結果は**タップで上書きできる**（○△×の3択。「解けたが怪しかった」を△に落とす用途。上書きは grade のみで `answer` は入力のまま送る）
- `answerType` の無い問題は従来どおり**○ / △ / × を必ずタップ**
- 全問に grade が揃うまで「感想へ」ボタンは無効（自動採点分は最初から揃っている）
- 採点状態はローカル state。まだ送信しない

### 3.4 当日の感想

- テキストエリア1つ（プレースホルダ「どこで詰まった？何が腑に落ちた？（1〜2行）」・空でも進める）
- ボタン「完了」で: ① `POST .../result`（grades＋各問の `answer`（フォーム入力があった問題のみ）＋feeling）→ ② 成功したら `POST /api/days/today/checks/{taskId}`（taskId が無いクエリなら省略）→ ③ 完了画面（「記録しました。明日のセットに反映されます」）→「今日へ戻る」

## 4. 状態と縁ケース

| 事象 | 挙動 |
|---|---|
| セットが無い（404） | 「今日の学習セットはありません（生成失敗か休み。ログ: night-study）」とだけ表示 |
| 途中離脱 | ローカル state のみ・永続しない。再訪時は最初から（1セット10分想定なので復元機構は作らない） |
| result 送信済みの日に再訪 | 記録済みの採点・回答入力・感想を表示し「やり直す」ボタンで再度一本道（result は UPSERT・上書き） |
| result POST 失敗 | トーストで再試行。checks は result 成功後にしか呼ばない（記録なしに消し込まれるのが最悪ケース） |
| 過去日の `?date=` 直叩き | 表示・採点とも可（仕様上は動く）が、導線は作らない（当日集中） |
