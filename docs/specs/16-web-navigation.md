# 16. ナビゲーション改訂仕様（ヘッダー＋ドロワー）

**親**: [`00-overview.md`](./00-overview.md) ｜ **担当**: Frontend ｜ **範囲**: `shared/ui/`（TabBar 廃止 → Header/Drawer）・`app/layout.tsx`

## 1. 目的

画面が増えてきた（今日・履歴・ルーティン・ダイジェスト・夜勤、今後 Phase 2 でさらに増加）ため、下部固定タブバー（3タブ）を廃止し、**ヘッダーのハンバーガー＋ドロワー**へ移行する。

毎日触るのは実質「今日」だけで、他画面はすべて低頻度——という使い方に合わせ、**ホーム＝今日、他は全部ドロワー**に格納する（2026-07-29 決定）。画面幅に関わらずハンバーガー1本に統一し、デスクトップ常設サイドバーは作らない（自分専用・スマホ主体のため。同日決定）。

## 2. 入出力

- **入力**: なし（ナビゲーションのみ。API 呼び出しなし）
- **出力**: 画面遷移（`next/link`）

## 3. 処理詳細

1. **下部タブバー（`shared/ui/TabBar.tsx`）を廃止**する。`.shell` の下部 padding（タブ分 96px）も撤去
2. **ヘッダー**: 既存の HUD ステータス行（通常は `ROUTINE / DAILY`、オフィスだけ `ROUTINE / OFFICE`＋画面タグ）にハンバーガーボタンを追加する（行を増やさない。今日画面のファーストビューを侵食しないため）
3. **ドロワー**: ハンバーガータップでオーバーレイ表示。項目は以下の8つ（上から使用頻度順。**2026-07-29 夕方改訂**——初版はダイジェスト・夜勤を含む5項目で当日実装したが、実物を見たユーザー判断で「タスク起点の詳細ビューは常設ナビに置かない」に戻し、開発履歴（[`19-web-dev-history.md`](./19-web-dev-history.md)）を加えた。2026-08-10 に外部の脳ビュー `brain` を追加。2026-08-22 に「オフィス」（[`20-web-office.md`](./20-web-office.md)）を追加。2026-08-29 に「あなた待ち」（[`23-web-waiting.md`](./23-web-waiting.md)）を追加）:
   - 今日（`/`）
   - 履歴（`/history`）
   - ルーティン（`/routines`）
   - あなた待ち（`/waiting` → [`23-web-waiting.md`](./23-web-waiting.md) の実装時に追加。承認2画面はハーネスの隣に並べる）
   - ハーネス（`/harness` → [`18-web-harness.md`](./18-web-harness.md) の実装時に追加）
   - 開発（`/dev` → [`19-web-dev-history.md`](./19-web-dev-history.md)）
   - オフィス（`/office` → [`20-web-office.md`](./20-web-office.md)）
   - brain（脳ビュー。HTTPS 本番では Tailscale Serve の `/brain`、HTTP プレビューでは同一ホストの `:48320`。cerebellum 外部のためアクティブ表示なし）
4. 項目タップで遷移してドロワーを閉じる。バックドロップ（外側）タップでも閉じる
5. 現在画面の項目はアクティブ様式（旧タブの active 様式を流用）。判定はパス前方一致（`/` のみ完全一致）＝旧 TabBar と同じ
6. **読む系のタスク起点詳細ビュー（ダイジェスト・夜勤・学習）はドロワーに入れない**。入口は「今日」のタスク行（detailRef 導線）で、過去の run を後から見たいときは「開発」（19）から辿る。**ハーネスと「あなた待ち」だけは例外として常設**（いずれも毎朝の承認**操作**であり、読むだけの詳細ビューとは性質が違う——2026-07-29 ユーザー判断・2026-08-29 に「あなた待ち」を同じ理由で追加）。「開発」「オフィス」はタスク行起点ではなく**常設の一覧**なのでこの規則の対象外

## 4. 設定値・確定値

- 画面幅によるレイアウト分岐なし（md 以上でもハンバーガーのまま。常設サイドバー不採用・2026-07-29）
- ドロワーは `shared/ui/` に置く（feature ではない。全画面共通シェルの一部）
- 遷移先の追加はドロワー項目リスト1箇所の編集で完結させる（旧 TABS 配列と同じ形）
- タップターゲット 44px 以上（[`07-web-foundation.md`](./07-web-foundation.md) §4 のモバイル規約に従う）

## 5. インターフェース

- 構成規約（`app → features → shared`・barrel 経由）: [`07-web-foundation.md`](./07-web-foundation.md) §3
- ドロワーはナビゲーションのみを持ち、feature を import しない

## 6. エラー処理

- なし（静的ナビゲーションのみ）

## 7. スコープ外

- デスクトップ常設サイドバー（不採用と決定済み。将来必要になったらこの仕様を改訂する）
- ドロワー内への**通知**（プッシュ）（Phase 2）。**件数バッジは 2026-09-02 にスコープ内へ改訂**——「あなた待ち」に未決の総件数を出す（[`25-web-inbox.md`](./25-web-inbox.md) §3.5 が正本。同 §3.5 は本仕様 §3-3 の改訂として書かれている）。他の項目にバッジは持たせない
- 画面の追加・削除そのもの（各画面仕様の責務）

## 8. 見た目

- 専用のデザイン仕様・プロトタイプは**作らない**（[`10-web-routines.md`](./10-web-routines.md) §と同じ方針）。トークンは `docs/design/system/01-tokens.md`、様式は旧タブ・既存画面から流用する
- 実装後に `docs/design/01-shell.md`（共通シェルの正本）をタブバー→ヘッダー＋ドロワーへ追従更新する
