# 16. ナビゲーション改訂仕様（ヘッダー＋ドロワー）

**親**: [`00-overview.md`](./00-overview.md) ｜ **担当**: Frontend ｜ **範囲**: `shared/ui/`（TabBar 廃止 → Header/Drawer）・`app/layout.tsx`

## 1. 目的

画面が増えてきた（今日・履歴・ルーティン・ダイジェスト・夜勤、今後 Phase 2 でさらに増加）ため、下部固定タブバー（3タブ）を廃止し、**ヘッダーのハンバーガー＋ドロワー**へ移行する。

毎日触るのは実質「今日」だけで、他画面はすべて低頻度——という使い方に合わせ、**ホーム＝今日、他は全部ドロワー**に格納する（2026-07-29 決定）。画面幅に関わらずハンバーガー1本に統一し、デスクトップ常設サイドバーは作らない（自分専用・スマホ主体のため。同日決定）。

## 2. 入出力

- **入力**: なし（ナビゲーションのみ。API 呼び出しなし）
- **出力**: 画面遷移（`next/link`）

## 3. 処理詳細

1. **下部タブバー（`shared/ui/TabBar.tsx`）を廃止**する。`.shell` の下部 padding（タブ分 96px）も撤去
2. **ヘッダー**: 既存の HUD ステータス行（`ROUTINE / DAILY`＋画面タグ）にハンバーガーボタンを追加する（行を増やさない。今日画面のファーストビューを侵食しないため）
3. **ドロワー**: ハンバーガータップでオーバーレイ表示。項目は以下の5つ（上から使用頻度順）:
   - 今日（`/`）
   - 履歴（`/history`）
   - ルーティン（`/routines`）
   - ダイジェスト（`/digest`）
   - 夜勤（`/nightshift`）
4. 項目タップで遷移してドロワーを閉じる。バックドロップ（外側）タップでも閉じる
5. 現在画面の項目はアクティブ様式（旧タブの active 様式を流用）。判定はパス前方一致（`/` のみ完全一致）＝旧 TabBar と同じ
6. 学習セッション（[`15-web-learning.md`](./15-web-learning.md)）はドロワーに**入れない**（当日集中モデル・タスクからの一本道のため）。ダイジェスト・夜勤の「タスクからの導線」も従来どおり残す（ドロワーは追加の入口であって置き換えではない）

## 4. 設定値・確定値

- 画面幅によるレイアウト分岐なし（md 以上でもハンバーガーのまま。常設サイドバー不採用・2026-07-29）
- ドロワーは `shared/ui/` に置く（feature ではない。全画面共通シェルの一部）
- 遷移先の追加はドロワー項目リスト1箇所の編集で完結させる（旧 TABS 配列と同じ形）
- タップターゲット 44px 以上（[`07-web-foundation.md`](./07-web-foundation.md) §4 のモバイル規約に従う）

## 5. インターフェース

- 構成規約（`app → features → shared`・barrel 経由）: [`07-web-foundation.md`](./07-web-foundation.md) §3
- ドロワーはナビゲーションのみを持ち、feature を import しない

## 6. エラー処理

- なし（静的ナビゲーションのみ）

## 7. スコープ外

- デスクトップ常設サイドバー（不採用と決定済み。将来必要になったらこの仕様を改訂する）
- ドロワー内への通知バッジ・件数表示（Phase 2 の通知と一体で設計）
- 画面の追加・削除そのもの（各画面仕様の責務）

## 8. 見た目

- 専用のデザイン仕様・プロトタイプは**作らない**（[`10-web-routines.md`](./10-web-routines.md) §と同じ方針）。トークンは `docs/design/system/01-tokens.md`、様式は旧タブ・既存画面から流用する
- 実装後に `docs/design/01-shell.md`（共通シェルの正本）をタブバー→ヘッダー＋ドロワーへ追従更新する

## 9. 関連仕様
