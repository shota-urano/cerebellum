# 29. 「あなた待ち」の決着済み表示と日付切り替え（Frontend）

**親**: [`00-overview.md`](./00-overview.md) ｜ **担当**: Frontend ｜ **範囲**: `app/waiting/page.tsx`・`features/inbox/`・`shared/ui/DateNav.tsx`（`features/history/` から移設）

[`25-web-inbox.md`](./25-web-inbox.md)（confirmed・実装済み）への**増分**。kind の並び順・固定文言・決定ボタン・失敗枠・未着判定（25 §3.2・§3.3）は変更しない。**変えるのは「今日決めたもの」の出どころと、過去日を読む導線だけ**。[`28-inbox-history.md`](./28-inbox-history.md) の `?date=` を消費する。

本仕様は 25 §7 のスコープ外「過去日の項目閲覧・検索」のうち、**閲覧を解除する**（検索は据え置き）。

## 1. 目的

25 §3.2 の「今日決めたもの」は、決定 POST の応答をキャッシュへ差し込んで描いている（`useInboxDecision` が `revalidate: false` を指定し、`partition` が `status !== 'open'` を拾う）。これは**そのタブが再取得するまでの見かけ**でしかない。一覧の取得は `?status=open` の1本なので、リロード・タブ復帰（`SWR_OPTIONS.revalidateOnFocus: true`）のいずれかで決着行が落ちる。

結果、「読んだ印を付けるだけ」と書いてあるボタンが、押して画面を切り替えて戻ると本文ごと消える。誤タップの救済路（25 §3.2）も、救済できるのは同じタブに留まっている間だけになっている。28 が読み出し口を足すので、画面はキャッシュ残骸ではなく**サーバの状態**を描く。

あわせて、決着した項目を後から読み返す導線を作る。「あの日何が届いて自分がどう決めたか」は、決定を機械が適用した後に効果を確かめるとき（24 §3.4 の書き戻し）と、送信元の出しすぎを見直すときに要る。

## 2. 入出力

- **入力**: `GET /api/inbox/items?status=open`（既存）／`GET /api/inbox/items?applyState=failed`（既存）／`GET /api/inbox/items?date=YYYY-MM-DD`（[`28`](./28-inbox-history.md)）／`office.json`（既存・未着判定）
- **出力**: `POST /api/inbox/items/{id}/decision`（既存・**今日のビューからのみ**）
- **経路**: `/waiting`（今日）・`/waiting?date=YYYY-MM-DD`（その日）・`/waiting?kind={kind}`（既存のフィルタ・今日のビューでのみ有効）

## 3. 処理詳細

### 3.1 今日のビュー（`date` 省略時・25 §3.2 の置き換えは1点だけ）

構成は 25 §3.2 のまま（上から: 未着行 → 未処理の失敗 → kind 別の未決グループ → 今日決めたもの）。変えるのは最下段の出どころ。

1. **「今日決めたもの」は `?date={今日}` の結果から `status !== 'open'` の行を抽出して描く**。`?status=open` の取得結果から拾うのをやめる。これでリロード・タブ復帰でも消えない
2. 未決グループは従来どおり `?status=open`（**日付では引かない**。未決は業務日をまたいで残るため。25 §3.2）。`?date={今日}` にも今日届いた未決が含まれるが、1 の抽出条件で落ちるので二重に出ない
3. 決定・取り消しの optimistic update は 25 §6 のまま。ただし成功後に **`?date={今日}` のキーも再検証する**（決着行がサーバ由来の下段へ移るため）。`?status=open` 側は従来どおり応答差し込みで済ませる
4. 適用済み（`applyState` が `applied` / `failed`）の行が下段に混じる。24 §3.3-2 のとおり取り消せないので、25 §3.2 と同じく凍結の旨を出す

### 3.2 過去日のビュー（`?date=` 指定時）

**読み取り専用**にする（[`09`](./09-web-history.md) §3 の過去日と同じ姿勢）。

1. その日に届いた全項目を **1列・id 降順**で並べる。kind でグループしない・未決グループも作らない——過去日ビューの役割は「その日に何が届いて自分がどうしたか」を読むことで、決める場所ではない
2. 各行に現在の状態を出す（`未決` / `✅承認` / `❌却下` / `☑{選んだ label}` / `📄読んだ` / `⚠確認済`）。**決定ボタン・ラジオは出さない**。未決の行も「未決」と出すだけで、決めるのは今日のビュー（操作口が2箇所あると、同じ項目の状態が2画面で動いて追えなくなる）
3. `bodyMd` の展開・`refPath` の表示は今日のビューと同じ（25 §3.2）。**読み返しが目的なので本文が読めることが要件**
4. 失敗枠（最上部の「未処理の失敗」）と未着判定は**出さない**。どちらも「いま気づくべき異常」の枠で、過去日には意味が無い（未着は今日 due の突合＝25 §3.3）。その日の行が `failed` なら 2 の状態表示と `apply_error` の等幅表示で足りる
5. `?kind=` フィルタは過去日では無視する（グループしないため）
6. 空表示: `この日に届いたものはありません。`（確定文言）

### 3.3 日付ナビ

`features/history/components/DateNav.tsx` を **`shared/ui/DateNav.tsx` へ移設**して両画面で使う（feature 間 import 禁止・[`07`](./07-web-foundation.md) §3。props は変えず、`features/history` は import 元だけ差し替える外科的移設）。

- 前日／翌日ボタン＋日付表示。**翌日方向は今日まで**（未来へ進めない。09 §3 と同じ）
- 今日を表示しているときは 3.1 のビュー、それ以外は 3.2 のビュー
- 過去日から今日へ戻る導線を1つ置く（`今日` ボタン）
- カレンダー UI は作らない（09 §4 の決定を踏襲）

### 3.4 「今日」画面（`app/page.tsx`）への影響

無し。第3段の件数・未着行・赤点（25 §3.1）は `summary` から作っており、本仕様は触らない。

## 4. 設定値・確定値

- 過去日は読み取り専用（変更禁止）。決定は今日のビューだけが持つ
- 表示順はサーバ返却順（`?date=` は id 降順）。クライアントで再ソートしない（25 §4 と同じ）
- 過去日ビューは kind でグループしない・固定文言（25 §3.2 の表）を出さない。あれは「押すと何が起きるか」の説明で、押せない画面には出さない
- ドロワー（[`16`](./16-web-navigation.md)）は無変更。「あなた待ち」1項目のまま、日付は画面内で切り替える。未決バッジの件数も `?status=open` のままで、過去日の閲覧はバッジに影響しない

## 5. インターフェース

- `features/inbox` の barrel に `useInboxByDate`（`?date=` の取得フック）を足す。`InboxView` は `date` prop（省略時は今日）で 3.1 / 3.2 を切り替える
- `shared/ui/index.ts` に `DateNav` を公開。`features/history` は `shared/ui` 経由に切り替え、`features/history/components/DateNav.tsx` は削除する（二重定義を残さない）
- `shared/api/types.ts` は無変更（28 は既存 DTO を流用）

## 6. エラー処理

| 事象 | 表示 |
|---|---|
| 400（不正な date クエリ） | 「不正な日付」＋今日へ戻る導線（09 §6 と同じ） |
| `?date=` の 500・通信失敗 | ErrorBanner＋再検証待ち。今日のビューでは上段（未決・失敗）は描き続け、下段だけ `取得できません` にする——決める作業を履歴の障害で止めない |
| decision 400 / 404 | 25 §6 のまま（ロールバック＋理由） |

- カレンダーグリッド UI・月表示
