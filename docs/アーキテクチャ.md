# cerebellum アーキテクチャ

作成: 2026-07-25 / 状態: 確定（要件定義.md とセットで spec-writer の入力にする）

## 全体トポロジー

```
┌─ Mac（常駐・launchd） ─────────────────────────┐
│  cerebellum（Rustバイナリ1個）                    │
│  ├ 静的配信: Next.js export（rust-embed で内蔵）  │
│  ├ JSON API: axum                               │
│  ├ core: ルーティン表パーサ／due判定／スナップショット │
│  ├ store: SQLite（WAL）                          │
│  └ vault: md 読み取り専用アダプタ                  │
└──────────┬───────────────────────────────┘
           │ Tailscale（インターネット非公開）
     スマホ / PC ブラウザ
```

## リポジトリ構成（monorepo・確定）

```
cerebellum/
├ server/    Rust crate（core / adapters / api / cli）
├ web/       Next.js（App Router・静的export）
├ docs/      要件定義・アーキテクチャ・specs
└ Makefile   verify 一発（下記）
```

## バックエンド（Rust）

3層構成。Phase 2（下書き・承認・digest）は core と api にモジュールを足すだけで拡張する。

| 層 | 内容 | 方針 |
|---|---|---|
| core | 表パース・due判定（毎日/平日/週末/曜日）・task_id生成（sha1(間隔\|時刻\|内容)先頭12桁）・スナップショット確定 | **I/O依存ゼロの純ロジック**。post.py と同一仕様。fixtureテストで厚く固める |
| adapters | `vault`（fs読み取りのみ）／`store`（SQLite） | rusqlite＋WAL（確定・sqlx不採用）。アクセスは単一ワーカー経由、プールなし |
| api / cli | axum ハンドラ／clap サブコマンド | `cerebellum serve --port 3210` が本体。将来 `notify` 等を追加 |

- 静的アセットは **rust-embed でバイナリに内蔵**（確定）。デプロイ＝バイナリ1個
- 時刻は常にローカルタイム（Asia/Tokyo）。日付境界は深夜0時
- Vault が読めない場合（Drive同期中等）は 503＋エラーJSONを返し、クラッシュしない

## API（Phase 1）

```
GET  /api/days/{date}                 その日のタスク＋チェック状態。{date}="today" 可。
                                      過去日は readonly=true 付きで返す
POST /api/days/today/checks/{task_id} チェックのトグル。当日以外は 403
GET  /api/summary?days=7              直近N日の消化率サマリ
GET  /api/health                      自己診断（Vault読取可否・DB可否）
```

- スナップショット確定は `/api/days/today` 初回アクセス時に ensure（冪等）。日次ジョブは持たない

## フロントエンド（Next.js）

- App Router＋`output: 'export'`（SSRなし・API は同一オリジンの Rust へ）
- ページは2枚: `/`（今日・消し込み）／`/history`（日付ナビ＋過去日読み取り専用＋7日サマリ）
- データ取得: **SWR**（フォアグラウンド復帰時の自動再検証でスマホ運用に合う）
- スタイル: **Tailwind**
- Phase 1 で PWA の下準備（manifest・ホーム画面追加）まで。プッシュ通知は Phase 後半

## verify 契約（dev-loop 前提）

`make verify` 一発で機械判定:

1. `cargo test`（core の fixture テスト含む）
2. `cargo clippy -- -D warnings`
3. `web/`: lint ＋ `next build`（export 成功まで）
4. embed 込みのリリースビルドが通ること

## 決定記録

- rust-embed 採用（外部ディレクトリ配信は不採用）— デプロイをバイナリ1個にするため
- rusqlite 採用（sqlx 不採用）— 個人利用で async プールは過剰、ビルドも速い
- monorepo 採用 — verify 契約を1本にまとめ dev-loop に載せるため
