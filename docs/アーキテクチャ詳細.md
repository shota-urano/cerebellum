## 1. Rust（server/）

### 1.1 クレート構成 — クリーンアーキテクチャ（確定）

単一バイナリクレート（workspace不使用。Phase 2でも分割しない想定）。
層は `domain ← usecase ← adapters / infra` の4層。**依存は常に内側向きのみ**。

```
server/
├ Cargo.toml
├ rust-toolchain.toml        # stable 固定
├ tests/                     # 結合テスト（axum oneshot）
│ └ api_test.rs
└ src/
  ├ main.rs                  # Composition Root（DI組み立て）＋ clap dispatch
  ├ cli.rs                   # clap derive（Serve { port }）
  ├ config.rs                # 設定（後述）
  ├ domain/                  # ── エンティティ＋純ルール。依存ゼロ
  │ ├ task.rs                # Task・task_id = sha1("間隔|時刻|内容")[..12]
  │ ├ routine.rs             # md表パース（純関数 &str→Vec<RoutineRow>。post.py と同一仕様）
  │ ├ due.rs                 # due判定（毎日/平日/週末/曜日）
  │ └ day.rs                 # DaySnapshot・進捗計算
  ├ usecase/                 # ── アプリケーションサービス。**ポート（trait）はここで定義**
  │ ├ ports.rs               # trait VaultReader / TaskRepository / Clock
  │ ├ get_day.rs             # 日取得（today のスナップショット ensure 含む・冪等）
  │ ├ toggle_check.rs        # トグル（「当日のみ許可」のガードはここ。API層に置かない）
  │ └ get_summary.rs         # 直近N日サマリ
  ├ adapters/                # ── ポート実装（外側）
  │ ├ fs_vault.rs            # impl VaultReader（fs読み取りのみ）
  │ ├ sqlite_repo.rs         # impl TaskRepository（rusqlite・migration・全クエリ）
  │ └ system_clock.rs        # impl Clock（Local時刻。テストでは固定時刻の fake に差し替え）
  └ infra/                   # ── フレームワーク層
    ├ api/                   # axum。DTO⇔usecase の変換のみ（days / summary / health / error）
    └ assets.rs              # rust-embed 配信＋SPAフォールバック
```

**依存ルール**

- domain は何にも依存しない。usecase は domain とポートにのみ依存。adapters / infra が外側からポートを実装する（依存性逆転）
- 注入は `Arc<dyn Trait>`（動的ディスパッチ。この規模でジェネリクスの複雑さは不要）。組み立ては main.rs のみ
- `Clock` をポートにするのが肝：「今日」の判定が固定時刻でテストできる（日付境界・曜日判定のテストに必須）
- ビジネスルール（過去日は読み取り専用、スナップショット冪等性）は usecase 層に置く。API層は変換だけ

### 1.2 依存クレート（確定）

| 用途 | クレート | 備考 |
|---|---|---|
| Web | axum | tokio（rt-multi-thread, macros）と併用 |
| CLI | clap（derive） | |
| DB | rusqlite（**bundled** feature） | SQLite同梱でシステム依存ゼロ |
| 静的配信 | rust-embed | `#[folder = "../web/out"]` |
| JSON | serde / serde_json | DTOは `rename_all = "camelCase"` |
| 日時 | chrono | Local時刻。日付は `%Y-%m-%d` |
| ハッシュ | sha1_smol | task_id用 |
| エラー | thiserror（各層） + anyhow（main/CLIのみ） | |
| ログ | tracing + tracing-subscriber | |

### 1.3 状態とDBアクセス

- `AppState`（Arc）: 各 usecase（ポート実装を注入済み）＋ `Config`
- ポート・usecase のメソッドは**同期**で定義（rusqlite都合を全層に伝播させない）。axumハンドラからは `tokio::task::spawn_blocking` 経由で呼ぶ（実行スレッドをブロックしない標準形）
- Connection は `Mutex<Connection>` で単一保持（個人利用・プール不要）。`PRAGMA journal_mode=WAL` を起動時に設定
- migration は埋め込みSQLを起動時に適用（`PRAGMA user_version` で版管理）

### 1.4 エラー方針

- 層ごとに thiserror（`DomainError` / `UsecaseError` / 各adapterのエラー）
- API層は `ApiError` に集約し `IntoResponse` 実装。レスポンスは常に `{"error": {"code": "...", "message": "..."}}`
- Vault読み取り不能（Drive同期中等）→ 503 `vault_unavailable`。過去日への書き込み → 403 `readonly_day`。不正date → 400、未知task_id → 404
- panic はバグ扱い。ハンドラ内で `unwrap` しない

### 1.5 テスト（層ごとに手段が決まる）

- domain: fixtureテスト（実物の `人間のルーティン.md` をコピーした fixture を同梱。post.py の出力と一致することを担保）
- usecase: ポートの手書きfake（`FakeClock` 固定時刻・`InMemoryRepo`）で単体テスト。日付境界・過去日ガード・スナップショット冪等性はここで固める
- adapters: `Connection::open_in_memory()` でクエリ単位テスト
- infra/api: axum の `tower::ServiceExt::oneshot` で結合テスト（today取得→toggle→過去日403 の一連）

## 2. Next.js（web/）

### 2.1 構成（確定）

Next.js 15 / React 19 / TypeScript strict / App Router / `output: 'export'` / Tailwind v4。

**Feature-based 構成**（確定）。app/ はルーティングと合成だけの薄い層に保ち、機能は features/ に閉じる。

```
web/
├ next.config.ts             # output:'export'／devは rewrites で /api → localhost:3210
├ package.json
├ public/
│ ├ manifest.webmanifest     # PWA下準備（ホーム画面追加まで）
│ └ icons/
└ src/
  ├ app/                     # ルーティング層（featureを組むだけ。ロジック禁止）
  │ ├ layout.tsx             # viewport・テーマ・manifest読込
  │ ├ page.tsx               # 「今日」= day feature を合成
  │ ├ history/page.tsx       # 「履歴」= history + day(readonly) を合成（?date= クエリ方式）
  │ └ globals.css            # Tailwind @import
  ├ features/
  │ ├ day/                   # その日のタスク表示＋消し込み（今日/過去日で共用）
  │ │ ├ components/          # TaskList / TaskItem / ProgressHeader
  │ │ ├ hooks/               # useDay（SWR: /api/days/{date}）/ useToggleCheck（optimistic）
  │ │ └ index.ts             # 公開API（barrel。外からはここ経由のみ）
  │ └ history/               # 日付ナビ＋サマリ
  │   ├ components/          # DateNav / SummaryCard
  │   ├ hooks/               # useSummary（SWR: /api/summary）
  │   └ index.ts
  └ shared/                  # feature横断の共通層
    ├ api/                   # client.ts（fetcher）/ types.ts（Rust DTOと手動同期）
    ├ ui/                    # ErrorBanner 等の汎用UI
    └ lib/                   # date.ts 等のユーティリティ
```

**依存ルール（一方向・lintで縛らず規約として明記）**

- `app → features → shared` の一方向のみ。**feature間のimport禁止**（横断が必要になったら shared に降ろすか、app層で合成する）
- feature の外部公開は `index.ts`（barrel）経由のみ。内部ファイルへの直importは禁止
- 「履歴画面でタスク一覧を出す」は history が day を import するのではなく、`app/history/page.tsx` が両featureを並べて合成する

- 履歴は動的セグメント（`/history/[date]`）ではなく**クエリパラメータ方式**（静的exportと相性が良い標準解）
- 型共有は Phase 1 では手書き（`shared/api/types.ts` にRust DTOを写す）。コード生成は導入しない

### 2.2 データ取得・更新

- SWR標準設定（`revalidateOnFocus: true`）。スマホでアプリに戻った瞬間に最新化される
- チェックのトグルは **optimistic update**：`mutate` でUI即時反映 → POST → 失敗時ロールバック
- APIベースは同一オリジン相対パス（`/api/...`）。dev時のみ next.config の rewrites でRustへプロキシ

### 2.3 UI方針

- モバイルファースト（max-w-2xl中央寄せ・タップターゲット44px以上）
- ダークモードは `prefers-color-scheme` 追従（Tailwindの `dark:`）
- 過去日表示は消し込みUIを無効化し「読み取り専用」バッジを出す

## 4. ビルド・verify（Makefile）

ビルド順が重要：**web → server**（rust-embed が `web/out` を取り込むため）。

```
make verify:
  1. web:    npm ci（初回）→ lint → next build（out/ 生成）
  2. server: cargo fmt --check → cargo clippy -- -D warnings → cargo test
  3. release: cargo build --release（embed込みで通ること）
```

- dev中は `next dev`（rewritesでRustへプロキシ）＋ `cargo run -- serve` の2プロセス
- 本番は `cerebellum serve --port 3210` の1プロセスを launchd 常駐
